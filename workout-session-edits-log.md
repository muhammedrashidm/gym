# Workout Session Feature — Edit Log

Continuation of implementation started in a prior (credit-exhausted) session. This log records every file created/edited/deleted in this pass, in order, with the reason. Cross-reference with [`workout-session-update-feature-plan.md`](workout-session-update-feature-plan.md).

## Audit findings (state inherited from prior session, before any edits here)

- `pubspec.yaml`: duplicate `sqflite:` key (lines 39 and 64) — invalid YAML, breaks `flutter pub get`/`flutter --version` outright.
- Prior session pivoted from Drift to `sqflite` (documented in a pubspec comment) after an `analyzer` version conflict between `dart_mediatr` (needs `analyzer ^5`) and `drift_dev` (needs `analyzer ^6`), but the pivot was incomplete:
  - `core/database/tables/session_drafts_table.dart`, `core/database/tables/task_completion_drafts_table.dart`, `core/database/app_database.g.dart` still use `package:drift/drift.dart`, which is no longer a dependency — orphaned dead files, not imported by the real (sqflite-based) `app_database.dart`.
  - `features/workout_session/data/datasources/workout_session_local_datasource.dart` was never converted — still calls Drift APIs (`_db.into`, `.watchSingleOrNull()`, `SessionDraftsCompanion`, etc.) against the sqflite-based `AppDatabase`, which exposes a completely different plain-`Map`/raw-SQL API. This file does not compile.
- `core/live_session/session_sync_service.dart` pattern-matches `AuthState.authenticated` with fields `(user, workspaceProfile, clientProfile, staffProfile)` — the real (already-refactored) `AuthState.authenticated` only carries `(token, availableRoles, activeRole)`. No `clientProfile`/`staffProfile`/`workoutProfiles` exist anywhere on auth state.
- No mechanism anywhere in the app resolves "the logged-in member's own `clientProfileId`" — `ProfileCubit.loadProfile()` is itself a hardcoded mock (`// TODO: Load from repository`), and the JWT only carries role claims (`roleId`/`roleName`/`gymId`), never a profile id (confirmed server-side: `RequestContext.profileId`/`staffProfileId` are resolved via a per-request DB lookup in `jwt-auth.guard.ts`, not embedded in the token). `member_session_commands.dart`/`member_workout_session_cubit.dart` assume a `clientProfileId` is available up front, which nothing supplies.
  - Fix: backend's `GET /workout-profiles` already supports omitting `clientProfileId` to mean "mine" (`workout-profile.service.ts:161-184`, filters by `ctx.profileId`/`ctx.staffProfileId` when absent). Widening `WorkoutRepository.getWorkoutProfiles` to accept a nullable `clientProfileId` lets the member flow ask for "my own" profile without needing to resolve an id client-side at all.
- `member_workout_session_cubit.dart` resolves "today's DayPlan" by indexing `activeWeeklyPlan.dayPlans[dayIndex]` — off-by-one prone (1-based cursor vs 0-based list) and requires `WeeklyPlan.dayPlans` to be populated, which isn't guaranteed. Backend already exposes `GET /workout-profiles/:id/today` for exactly this. Adding `WorkoutRepository.getTodayPlan(workoutProfileId)` replaces this entirely.
- Mediator call convention used (`_mediator.send<Q, Future<dynamic>>(...)`) doesn't match the established convention elsewhere in the codebase (`_mediator.sendCommand(SomeQuery(...)) as Either<Failure, T>`, see `AthleteProfileCubit`) — needs verifying against the actual `dart_mediatr` API and correcting.

## Edits (this pass)

1. `gym/pubspec.yaml` — removed duplicate `sqflite: ^2.4.2+1` line (line 64; the real entry is under the "Local database" section, line 39). This alone was fatal — `flutter --version`/`pub get` refused to parse the YAML at all ("Duplicate mapping key").
2. Deleted `gym/lib/core/database/app_database.g.dart`, `gym/lib/core/database/tables/session_drafts_table.dart`, `gym/lib/core/database/tables/task_completion_drafts_table.dart` — dead Drift-era files left behind after the prior session pivoted `AppDatabase` to sqflite. They still `import 'package:drift/drift.dart'`, which is no longer a dependency, so they'd fail analysis; nothing else imports them (the real `app_database.dart` is plain sqflite with no `part` directive).
3. `gym/lib/features/workout/domain/repositories/workout_repository.dart`, `data/datasources/workout_remote_datasource.dart`, `data/repositories/workout_repository_impl.dart`:
   - Widened `getWorkoutProfiles(String clientProfileId)` → `getWorkoutProfiles(String? clientProfileId)` (positional, still required so all 4 existing call sites compile unchanged) and only send the `clientProfileId` query param when non-null. The backend (`workout-profile.service.ts:161-184`) already treats an omitted `clientProfileId` as "my own profiles" (member) / "my assigned clients" (trainer) via `ctx.profileId`/`ctx.staffProfileId` — there was previously no way for the member session flow to fetch its own profile since nothing in the app resolves "my clientProfileId" from auth state (see audit above). This makes that possible without needing to resolve one at all.
   - Added `getTodayPlan(String workoutProfileId) → Future<Either<Failure, DayPlan?>>` wrapping `GET /workout-profiles/:id/today`. Replaces the member/trainer session cubits' original approach of indexing `profile.activeWeeklyPlan.dayPlans[dayIndex]` — which was doubly broken: (a) 1-based `currentDayIndex` indexed directly into a 0-based list, and (b) `getWorkoutProfiles`'s Prisma query only selects `activeWeeklyPlan: {id, name, status}` server-side (`workout-profile.service.ts:187-196`), so `dayPlans` is never actually populated on that path regardless.
   - Fixed `getSessionLogs` response parsing: it read `data['sessions']`/`data['total']`/`data['page']`/`data['pageSize']` at the top level, but the real envelope (`workout-session-api.md` §2.3, confirmed against `workout-session.controller.ts`) is `{success, data: [...], meta: {total, page, pageSize}}` — the old keys never existed in the response, so pagination/list would have silently returned an empty list with parsed defaults.
4. Rewrote `gym/lib/features/workout_session/data/datasources/workout_session_local_datasource.dart` from scratch against the real sqflite-based `AppDatabase` (raw `Map<String,dynamic>` rows, no Drift). Added a broadcast `StreamController<void>` that fires after every write; `watchDraft`/`watchAllActiveDrafts` emit once immediately then again on every subsequent write signal (poll-on-write — sqflite has no native change stream, unlike the Drift API this file used to assume).
5. `domain/usecases/member_session_commands.dart`: removed invalid `const` on `GetMemberActiveProfileQuery` (its `ICommand` superclass has no const constructor — this alone was a compile error), made its `clientProfileId` an optional positional `[String?]` (null → "my own", per fix #3), and deleted `GetDayPlanForSessionQuery`/Handler (replaced by #6 below). Added an explicit `package:collection/collection.dart` import for `.firstOrNull` — it was relying on an unconfirmed transitive/ambient availability; `collection` is now also a direct `pubspec.yaml` dependency instead of only transitive.
6. New `domain/usecases/get_today_plan_query.dart`: `GetTodayPlanQuery(workoutProfileId)` wrapping `WorkoutRepository.getTodayPlan`. Shared by both member and trainer cubits (identical behavior for both roles, so not duplicated per-role like the complete/skip/logs commands are).
7. `domain/usecases/trainer_session_commands.dart`: removed invalid `const` on `GetClientWorkoutProfileQuery`; added the same explicit `collection` import.
8. Renamed all freezed variant redirect classes from private (`_Loaded`, `_Error`, etc.) to public names (`MemberSessionLoaded`, `MemberSessionError`, `TrainerSessionLoaded`, `TrainerSessionError`, `LiveClientsLoaded`, etc.) in `member_workout_session_state.dart`, `trainer_client_session_state.dart`, `trainer_live_clients_state.dart`. The prior private names made `state is _Error`-style checks in the cubit files impossible to compile (freezed's generated `_Error` class is library-private to the state file; the cubit is a different library) — this also matches the existing convention in `auth_state.dart`, which documents itself as using public names specifically so cross-file `is` checks work.
9. Rewrote `presentation/cubit/member_workout_session/member_workout_session_cubit.dart`:
   - `loadSession()` no longer takes a `clientProfileId` — it calls `GetMemberActiveProfileQuery()` with no argument, resolved server-side via fix #3.
   - Replaced the `activeWeeklyPlan.dayPlans[dayIndex]` lookup (off-by-one prone, and `dayPlans` isn't even populated on the `getWorkoutProfiles` response — see #3) with `GetTodayPlanQuery`.
   - Normalized mediator calls to the codebase's established `_mediator.sendCommand(x) as Either<Failure, T>` pattern (was `_mediator.send<Q, Future<dynamic>>(...)`, which happened to work at runtime via the shared handler map but typed everything as `dynamic`, discarding compile-time checking).
   - Fixed a real logic bug: when `GetMemberActiveProfileQuery` succeeds with `null` (no active program — not an error), the old code did `if (profile == null) return;` and silently stayed on the loading spinner forever instead of emitting `noPlan()`. The error-vs-empty-success cases are now handled separately.
   - Fixed the `state is _Error` cross-library reference (see #8) by switching to `state is MemberSessionLoaded` via a small `_currentLoaded()` helper.
10. Rewrote `presentation/cubit/trainer_client_session/trainer_client_session_cubit.dart` with the mirror set of fixes (today-plan query, sendCommand convention, success-null-vs-error distinction, public state names).
11. Rewrote `presentation/cubit/trainer_live_clients/trainer_live_clients_cubit.dart`: the previous version expected an already-built roster of `(profileId, name, avatarUrl, workoutProfileId)` records to be handed in from the page, and matched local drafts by `workoutProfileId` — but nothing anywhere resolves a trainer's clients' `workoutProfileId`s in bulk (no such endpoint exists), so that roster could never actually be constructed. Fixed by having the cubit fetch its own roster via the existing `ListStaffClientsQuery` (same query `staff_clients_page.dart` already uses) and matching local drafts by `clientProfileId` instead — every `SessionDraft` already carries `clientProfileId`, so no bulk workout-profile lookup is needed at all.
12. Rewrote `core/live_session/session_sync_service.dart`: the auth-state branch pattern-matched `AuthState.authenticated(user, workspaceProfile, clientProfile, staffProfile)` — fields that don't exist; the real (already-refactored) `AuthState.authenticated` only carries `(token, availableRoles, activeRole)`, and there is no `clientProfile`/`staffProfile`/`workoutProfiles` concept anywhere in auth state (confirmed: the JWT only carries role claims; the app has no working "get my own profile id" call anywhere — `ProfileCubit.loadProfile()` is itself still a hardcoded mock). Fixed to branch on `activeRole.roleEnum` (`Role.member`/`Role.staff`), and unified both branches to use `watchAllActiveDrafts()` (a member's device naturally only ever has ≤1 row, so no separate single-draft path is needed).
13. `presentation/pages/weekly_plan_page.dart`: removed the hardcoded `'MEMBER_CLIENT_PROFILE_ID'` placeholder from both `loadSession()` calls (now no-arg, per #9). Fixed a day-strip off-by-one: `currentDayIndex` is 1-based (1..7) but the header text added `+1` and the day-strip comparison used a bare 0-based `index` — now `Day ${profile.currentDayIndex}` and `currentDayIndex == index + 1`.
14. `presentation/pages/trainer_client_session_page.dart`: same day-strip off-by-one fix as #13.

Removed an unused `app_routes.dart` import and an unused `totalTasks` local variable that computed a fabricated "+3 tasks" total that was never actually derived from the day plan.

17. `core/di/injection.dart`: registered `GetTodayPlanQueryHandler` in place of the deleted `GetDayPlanForSessionQueryHandler`.
18. Added `collection: ^1.18.0` as an explicit `pubspec.yaml` dependency (see #5).

Fixed relative-import off-by-one in all three state files (`member_workout_session_state.dart`, `trainer_client_session_state.dart`, `trainer_live_clients_state.dart`) — each was missing one `../` level (e.g. `../../../workout/domain/entities/workout_profile.dart` instead of `../../../../workout/domain/entities/workout_profile.dart`), so every import in these files pointed at a nonexistent path. This was the single largest source of cascading `undefined_class`/`uri_does_not_exist` errors (700+ reported by `dart analyze`, all downstream of these 11 broken import lines) — confirmed by directly resolving each relative path against the actual directory tree rather than guessing.
